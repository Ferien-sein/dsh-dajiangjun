## 0. 一句话

插件提供一个工具：当前会话的 agent 写完交接档后调用它，插件校验档、过闸门、建一个新会话、命名、投递"接手指令"，新会话自己开工。**缺省只预览，不真做。**

## 1. 目标与非目标

### 目标（v1 必须做到）

| # | 目标 | 验收方式 |
|---|---|---|
| G1 | 交接档**结构契约**校验：七段齐全、段标题逐字匹配、第 5 段有非空有序列表首项、主线名可解析 | 单测（正例 + 三条反例） |
| G2 | 缺省 `dryRun`：不传参数返回"将做什么"，且**零真副作用**（不建会话、不改档、不投递、不占锁）。审计会追加一行并标 `dryRun:true`，而**所有计数逻辑一律忽略 `dryRun:true` 的行**——否则"预览两次被拒"会经失败闸把自己锁死 | 单测断言调用后无新会话、无 `dryRun:false` 审计行、三个计数值不变 |
| G3 | 显式 `dryRun:false` 时执行完整链：建会话 → 命名 → 投递 → 回写档头 → 审计 | 隔离 profile 端到端实跑 1 条 |
| G4 | 新会话**真的自己开工**（这是 v1 的存在理由） | 端到端实跑观察新会话状态转 `running` 且有 assistant 产出 |
| G5 | 权限不降级：新会话真实继承的沙箱档位 < 源会话 → 不投递 | 构造"只读源会话"用例，验退出码 5 且未投递 |
| G6 | 一个源会话只许交接一次（去重键）+ 同一时刻只有一个接力在跑（单飞锁） | 单测：并发 10 次只 1 次执行、其余退出码 0 |
| G7 | 审计 append-only + `prevHash` 哈希链，每个闸门动作留一行 | 单测：断链能被检出 |
| G8 | 总开关初值 = **关** | 出厂配置即如此；关闭时工具返回"未启用"且零副作用 |
| G9 | 交接档四类禁写内容在**组装投递请求之前**被拦 | 单测：凭据形态 / 内网地址 / 他人隐私 / 会话原文各一例 |
| G10 | **主动提醒**（§13）：上下文越过软限时让 agent 知道"该交接了"，不依赖它自觉 | 单测：抑制三条（变化阈值/冷却/日上限）各一例 + 开关关闭时零副作用 |

### 非目标（v1 明确不做，逐条给理由）

| # | 不做 | 理由 |
|---|---|---|
| N1 | 无人值守定时通道（越限自动触发、单日 ≤1 次、原子预占） | 候选面判据是"命中**工单执行会话**且 `running=true`"，而 `SessionHeader`/`SessionSummary` **没有任何工单字段**（已核实）。要做得先自建工单映射，那是另一个项目 |
| N2 | 在途工单改绑 | 同上，无工单概念 |
| N3 | 标题三轴机（状态轴/任务轴/接力轴）+ 分层解析 + ≤59B 字节预算分配 | 本机 `dsh-session-title` **不存在任何前缀重写层**（已核实），那个 59ms 丢轴 bug 的成因在这里不成立；`normalizeSessionTitle` 会安全截断，不需要手算字节预算 |
| N4 | 静态权限断言（配置键 vs 启动链源码字面常量） | 见 §6 的 `ponytail:` 说明 |
| N5 | 成本闸（按 token 预算） | 默认 0 = 不启用，v1 留参数位不实现逻辑 |
| N6 | 深度保险丝 | 去重键（一个源只交一次）已兜底 |
| N7 | 客户端 UI 半体 | v1 的可见性靠工具返回值 + 审计文件就够。**这直接省掉一半工作量与一套构建链** |
| N8 | 跨机接力 | 文档 09 自己明示不做；且本机只有一台 |
| N9 | 自动收拾孤儿/残留会话 | 文档 09 原文：只报不收拾（归档不可逆） |
| N10 | 改源会话标题为 `【已交接】` | 那一步在原设计里由**接手方**执行（动作链第 ③ 步），v1 不替接手方做 |

## 2. 架构

### 2.1 组件

**一个宿主插件，三个源文件。**

| 文件 | 职责 | 为什么分开 |
|---|---|---|
| `lib/index.js` | cordis 入口：`name` / `inject` / `Config` / `apply(ctx)`，注册工具 | 只有它碰 `ctx`，便于单测替身 |
| `lib/relay.js` | **纯逻辑**：档结构校验、禁写内容检查、闸门判定、链标识生成 | 无 I/O、无 `ctx` → 可直接单测 |
| `lib/store.js` | 审计 append-only + 原子写 + 单例锁 | 三个功能都要碰文件系统，且**其他能力将来会复用** |

> 关于原先设想的 "S0 地基"：**它不是独立阶段，就是 `lib/store.js` 这一个文件里的三个函数**。单独建阶段只是多一份架构，不产出任何新能力。

另有 `package.json`、`cordis.patch.yml`、`lib/types/index.d.ts`、`README.md`、`test/relay.test.js`。

### 2.2 为什么没有客户端半体

v1 的一切都是"agent 调工具、拿文本结果"。加 `lib/client.js` 要多一套构建产物链 + 槽位选择 + 前端状态同步，而它换来的只是把同样的文本渲染得好看一点。**等真需要"一块能看的接力状态"时再加。**

### 2.3 依赖的服务

| `ctx` 上的服务 | 用途 | 证据 |
|---|---|---|
| `ctx.tools` | 注册工具 | `dsh-tools` |
| `ctx.sessionController` | `create()` / `prompt()` | `dsh-api-session-controller` |
| `ctx.sessionTitle` | `rename()` | `dsh-session-title` |
| `ctx.sessionProjections` | 回读真实继承的沙箱档位 | `dsh-session-projection` |
| `ctx.settings` **不用** | 0.2.0-rc.2 无 `register()`；命名空间就是本插件的 `Config` | 已核实 |

> `inject` 数组里的**服务名字符串**（如 `sessionController` 的确切键名）需在实现时从各包的服务声明确认，不从本文档推断。

## 3. 数据流

```
① agent 自己写档（用普通 fs 工具，插件不代笔）
     ↓  路径：<DSH_HOME>/steward/relay/<主线名>-<yyyymmdd-HHmm>.md
② agent 调 steward_relay({ mainline, docPath })          ← dryRun 缺省 = true
     ↓
③ 读档 → 结构契约校验 → 四类禁写内容检查
     ↓ 不过 → 返回 kind:'rejected' + 具体原因，零副作用
④ 闸门（§5 的 8 道中，**除单飞锁外的 7 道**，全过才继续）
     ↓ 不过 → 返回 kind:'rejected' + 闸门名 + 退出码（审计行标 dryRun，不参与计数）
⑤ dryRun? ─── 是 ──→ 返回 kind:'preview'（将建会话 / 将用什么标题 / 将投什么内容 / 将改哪些文件）
     │
     否
     ↓
⑥ 单飞锁（键 = 源会话 id）→ 抢不到则退出码 0，静默返回
     ↓
⑦ agent.create({ sessionId:<新>, cwd:<同源> })
     ↓
⑧ 权限回读断言：新会话 sandboxMode ≥ 源会话档位？
     ↓ 不满足 → 不投递 → 处置新空会话（见 §8 待确认 A1）→ 退出码 5
     ↓
⑨ sessionTitle.rename(新会话, `【续】<主线名>`)
     ↓
⑩ sessionController.prompt({ sessionId:<新>, mode:'queue', content:[接手指令] })
     ↓        ↑ mode 必须是 'queue'——见 §7 红线
     ↓
⑪ 回写档头：新增 relayId / 已交接时间 / 新会话 id
     ↓
⑫ 追加审计行 → 释放锁 → 返回 kind:'dispatched'
```

### 3.1 接手指令的内容

保持短（省 token），只给三样：

```
读交接档 <docPath>，按第 5 段「下一步」逐条继续。
你是接力会话；链标识 <relayId>；主线 <mainline>。
开工前先读档全文，不要只看这一段。
```

### 3.2 链标识

`relay-<源会话id>-<yyyymmddHHmm>`。同时写进：审计行 / 档头 / 接手指令 / 工具返回值。**它是唯一串联键**——原设计要求一条链跨 4 组件 6 动作，v1 只有 1 组件 3 动作，但键的形态保持一致，将来接别的组件不用改口径。

## 4. 交接档结构契约

七段，段标题**逐字固定**，按行前缀匹配（容忍前面的 `#` 与空白）：

| 段 | 标题（逐字） | 校验规则 |
|---|---|---|
| 1 | `头部` | 键值行，必须含 `主线:`；可选 `源会话:` `时间:` `链:` |
| 2 | `现状` | 非空，一句话 |
| 3 | `已完成` | 每项须带证据路径（含 `/` 或 `\` 的 token） |
| 4 | `在途` | 允许空（写"无"） |
| 5 | `下一步` | **必须**含 ≥1 行有序列表项（`1. ` 开头）且内容非空 |
| 6 | `待拍板` | 允许空（写"无"） |
| 7 | `速查` | 路径速查 + 红线 |

**不通过 = 不建会话**（闸门 8，fail-closed）。

**主线名取值序**：段 1 的 `主线:` 值 → 档文件名里 `<主线名>-<时间戳>` 的第一段 → 都取不到则**拒绝接力**（不猜）。

### 4.1 三条反例（进单测）

1. 有 `下一步` 段标题但下面全是散文、无有序列表 → 拒
2. 七段齐全但 `已完成` 项无任何证据路径 → 拒
3. 段标题写成 `## 下一步是什么` → 拒（逐字匹配，不做模糊）

### 4.2 四类禁写内容（在组装投递请求之前检查）

| 类 | 检测 |
|---|---|
| 凭据值 | 形如 `sk-` 前缀长串、`Bearer <长串>`、`password=`/`token=` 后跟值 |
| 内网地址 | 非回环的私有网段 IP（`10.` / `192.168.` / `172.16-31.`）、`http://` 非 `127.0.0.1`/`localhost` 的 URL |
| 他人隐私 | 手机号 / 邮箱形态 |
| 会话原文 | 连续引用 ≥N 行（默认 5）以 `user:`/`assistant:` 开头的块 |

命中即拒，报命中类目与行号；**不把命中内容回显到工具输出**（否则等于把禁写内容搬进日志）。

## 5. 闸门（v1 保留 8 道 / 砍 4 道）

原设计 12 道。逐条处置：

| 原闸 | v1 | 理由 |
|---|---|---|
| 1 软限阈值 | **砍** | 本机无监控组件可"沿用既有阈值"。v1 由 agent 自行判断何时发起——这**正是原设计的主路径**（"到软限即由当前会话 agent 自己发起"）。工具在调用时记录当时的 token 用量供事后校准。`ponytail:` 无主动阈值提醒，等有观测数据再加 |
| 2 速率闸（同主线两次交接间隔 ≥20 min） | **留** | 防接力风暴。计数只算审计里**成功**的行，读当月 + 上月 |
| 3 失败闸（同主线连续失败 ≥2 次即停） | **留** | 廉价且防"坏了还一直试" |
| 4 成本闸 | **砍** | 默认 0 = 不启用，留参数位不实现 |
| 5 单飞锁（键 = **源会话**，不是链标识） | **留** | 链标识每次新生成，挡不住并发 |
| 6 深度保险丝 | **砍** | 去重键已兜底 |
| 7 去重键（`relay\|<源会话id>`，一个源只许交一次） | **留** | 核心防重 |
| 8 无"下一步"段 / 主线名取不到 → 不开会话 | **留** | 档契约的核心，fail-closed |
| 9 权限不降级 | **留** | 唯一真防线，见 §6 |
| 10 配置不可读 → 拒绝 | **留** | 不许把"读不到"实现成"全放行" |
| 11 动作总闸（两个开关，初值 = 关） | **留** | 03 R9 + 07 R2 的锁后交付 |
| 12 触发源额度（每会话每档 24h 1 条 + 池级日上限） | **砍** | 为无人值守通道设计；v1 无该通道。同源一次已由闸门 7 覆盖 |

**每道闸都必须有**：判据 / 不建会话的动作 / 审计行（带原因）/ 退出码 / 可见位置（工具返回值）。缺任一项不算合格闸门——这是文档 09 的硬要求。

## 6. 权限不降级：只做运行时断言

**做法**：`create()` 之后、`prompt()` 之前，回读新会话真实继承的沙箱档位（`sessionProjections.stateOf(session,'sandboxMode')` 与/或 snapshot），与源会话档位比较。比较**必须走序表**（`read-only < workspace-write < danger-full-access`），**不得用字符串比较**——字符串比较会正好反转。

不满足 → 不投递 → 退出码 5 → 审计行。

> `ponytail:` v1 不做静态断言（配置键 vs 启动链源码字面常量）。原设计的理由是"抓住配置与源码常量漂移"，但本插件是新写的、配置与代码同一次提交、且原设计自己也承认静态段"代表不了本次实际生效值"。代价：如果将来宿主改了注入点而我们的配置没跟，只有运行时段能发现——**这正是运行时段的职责**，所以不构成盲区。真要加，等出现第一次配置漂移事故。
>
> 原设计还写了一条"保护区写入一律走『写临时文件 → 审计 → 原子 rename 就位』"以避免副作用窗口。v1 **不适用**：我们不写保护区文件，只写自己的档 + 自己的审计。

## 7. 红线（选错就静默失败的地方）

| # | 红线 | 选错的症状 | 依据 |
|---|---|---|---|
| **R-1** | 投递**必须**用 `mode:'queue'` 或 `'steer'`，**绝不用** `inject` | 会话建好了、内容也在、**就是不跑**，且不报错 | `followup`/`steer` 的 `wakeup=true`，**只有 `inject` 是 `false`**（`dsh-agent-loop/lib/index.js:806-814`，已核实） |
| **R-2** | 权限档位比较**必须**走序表，不得字符串比较 | 恰好反转：只读被当成最高档放行 | 文档 09 原文明示 |
| **R-3** | 闸门判定读不到配置时，**拒绝**，不得当"全放行" | 一次文件损坏 = 链开了 | 文档 11 的 fail-closed 口径 |
| **R-4** | 单飞锁必须用 `flag:'wx'` **原子创建**，禁止"先 `existsSync` 再写" | TOCTOU → 双跑 | 文档 02 §5.6 |
| **R-5** | 状态文件必须原子写（临时文件 → `fs.rename`），禁止直接 `writeFileSync(目标)` | 半截写 = 文件损坏 | 文档 02 §5.6 |
| **R-6** | 命名冲突：同一 slot 同优先级二次注册会抛错；`root` 槽位是陷阱 | （v1 无客户端半体，暂不涉） | 已核实 |

## 8. 状态、审计与错误处理

### 8.1 状态文件

| 文件 | 位置 | 内容 | 丢失后果 |
|---|---|---|---|
| 审计流水 | `<DSH_HOME>/steward/audit/YYYY-MM.jsonl` | append-only，每行 `{ts, actor, actionId, params, dryRun, result, affectedCount, relayId, prevHash, hash}` | **不可重建** → 必须随备份走 |
| 去重/速率/失败计数 | 不单独存 | **从审计流水现算** | 无额外状态即无额外漂移点 |
| 单飞锁 | `<DSH_HOME>/steward/locks/relay-<源会话id>.lock` | `{pid, startedAt, ttl}` | 最多重复执行一次，由去重键兜底 |

> `ponytail:` 去重/速率/失败计数**不建独立状态文件**，直接从审计流水算。原设计列了 `steward-auto-actions.json` 等一堆状态文件；v1 只有一个真源，少一处漂移点。代价：审计流水变长后每次要扫；按"读当月 + 上月"限定范围即可，量级是每天个位数行。真慢了再加索引文件。

**持久化位置**：`<DSH_HOME>` 下，**不在临时目录**。理由（原设计的实测教训）：把降档/去重状态放临时目录，被清理后会静默放行自动动作，是 fail-safe 反转为 fail-open。

### 8.2 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功；**或**抢不到单飞锁（静默退出，不排队不重试）；**或** dry-run 预览成功 |
| 2 | 参数错 / 越权（调用者不是主会话、缺必填参数） |
| 3 | 部分完成（会话已建但后续某步失败，现场保留并报出） |
| 5 | 需人工 fail-closed（档不合格 / 闸门不过 / 权限降级 / 配置不可读） |
| 1 | 其它未预期错误 |

**半完成态只报不收拾**（归档不可逆）——文档 09 的硬要求。工具返回值必须带成因字段（一个枚举一个含义，缺成因会误判正常新会话）。

### 8.3 发起者白名单（闸门的一部分）

| 发起者 | 允许 |
|---|---|
| 主会话 agent | ✅ 完整链 |
| 子代理 | ❌（绕过"一条主线一个主"）——**判定方式**：`exec.parent` 存在即视为子代理 |
| 其它自动脚本 | ❌ v1 不接受 |
| 缺 actor 字段 | ❌ **拒绝**（fail-closed） |

## 9. 测试策略

按 ponytail 的"非平凡逻辑留一个可跑的检查"，不引测试框架，用 Node 24 自带的 `node:test` + `node:assert`。

`test/relay.test.js` 覆盖：

1. 档契约：正例通过；三条反例各自被拒且原因正确
2. 禁写内容：四类各一例被拒；命中内容**不出现在返回值里**
3. 主线名取值序：段 1 → 文件名 → 拒绝
4. 闸门：8 道各一个"不过"用例，验退出码与审计行
5. dryRun：断言调用后**无新会话、无审计转入**
6. 去重：同源第二次被拒
7. 单飞：并发 10 次只有 1 次真执行，其余退出码 0
8. 权限序表：三种档位两两比较，含"只读 vs 完全访问"的反转用例
9. 审计哈希链：篡改一行后断链能被检出

**端到端（隔离 profile，强制）**：一条真链，含失败注入——① 投递前杀进程 ② 构造不存在的档路径 ③ 只读源会话验退出码 5。
**`--dry-run` 不构成真链验收**（验证不了原子 rename 与注入时序）。

## 13. 主动提醒（阈值感知）

> 逻辑位置在 §5 与 §6 之间。编号放末尾是为了不打断已有的交叉引用。

### 13.1 为什么需要它

v1 砍掉了原设计的「软限阈值」闸门（§5 闸门 1），代价是**接力只在 agent 自己想起来时才会发生**。而"这活没人干"恰恰是原设计要解决的缺口（文档 09 原话：缺口不在检测，在交接动作）。本节唯一的职责：让"该交接了"这件事不依赖 agent 自觉。

### 13.2 做法：往系统提示追加一行，不制造回合

订阅 `system-prompt/assemble`（waterfall），当会话上下文用量越过软限时追加一行：

```
⚠ 本会话上下文已用 ~{pct}%，接近上限。准备交接：写完交接档后调用 steward_relay。
```

**为什么不是推一条 prompt 消息**：推消息（`sessionController.prompt`）会让模型**真的跑一个回合**去回应它——既烧 token，又把用量推得更高，形成"提醒 → 涨 → 再提醒"的自激循环。往系统提示加一行只要约 30 token、不产生新回合，且 agent 在之后的**每一次**请求里都看得到。

| 方案 | 额外成本 | 自激风险 | agent 可见性 |
|---|---|---|---|
| 推 prompt 消息 | 一个完整回合的 token | **有**（提醒本身涨用量） | 一次 |
| **系统提示追加一行** | 约 30 token / 请求 | 无 | 每次请求 |

### 13.3 抑制（防刷屏与自激）

- **只报状态变化**：同一会话仅在**首次**越过软限时追加；此后用量每再涨 **≥5 个百分点**才重新追加
- **冷却**：同一会话两次追加间隔 **≥20 分钟**
- **日上限**：全局每日 **≤10 条**（超出只记审计、不追加）
- **免打扰**：23:00–07:00 只记审计、不追加
- 计数一律从审计流水现算（§8.1 口径），**且忽略 `dryRun:true` 的行**

### 13.4 开关

独立开关 `notify.enabled`，**初值 = 关**；关闭时零副作用、零 token。

理由（03 R9）：它虽然只加一行提示，但属于"自主往外发东西"，不满足 R9「可直接执行」的四条件；按 07 R2 一律默认关、逐项放行。

### 13.5 阈值来源

软限比例 `notify.softLimitRatio`（默认 0.7），分母取自当前模型的上下文上限。

**回退路径**：取不到模型上限 → **不提醒**（不许猜一个分母）。见 §10 的 A9。

### 13.6 与 §5 闸门 1 的关系

闸门 1（软限阈值）仍然"砍"——**本节不构成闸门**，它不拦任何动作、不参与接力判定，只是让 agent 知道。原设计的"越限自动触发接力"（无人值守通道）仍在 N1 非目标里。
