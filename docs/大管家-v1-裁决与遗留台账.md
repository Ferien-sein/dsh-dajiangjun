## 4. 这套流程实际抓到了什么（供你判断它的性价比）

端到端一跑，**53 条单元测试 + 5 轮独立审查全过的情况下**，抓出 **5 个"假绿"**——同一个形态：

> `fakeCtx` 替身照着实现的假设写 → **代码与替身互相印证、一起错** → 测的是一个**不存在的 API 形状**。

| # | 缺陷 | 若发货的后果 |
|---|---|---|
| 1 | `resolveAgent()` 返回 `{agent}` 包装，写成 `.session` | 真链在权限断言处抛错，**完全不可用** |
| 2 | `sessionTitle.rename(session, title)` 第一参是 session 对象 | 改名失败 |
| 3 | `sessionController.prompt(request, signal)` 漏传 signal | 投递行为不可预期 |
| 4 | `event.data.usage` 误写成 `event.data.message.usage` | 提醒**永远取不到用量**、静默不生效 |
| 5 | `isSubagentCaller` 用 `exec.parent`（PTC 标记）判子代理 | 子代理拦不住；主会话在 `run_code` 里被误拒 |

另有 **4 个非"假绿"类**的缺陷被流程抓出并修掉：

- **坏测试命令**（`node --test test/` 在本机 Node 24 上**根本不加载测试文件**，7 处）——若不修，后续每个任务会把"测试没跑"当成"测试通过"；
- **跨月哈希链必然误报完整性告警**（每月一次假 🔴）；
- **锁原语漏审计行 + 损坏锁文件会让锁永久卡死**；
- **内网 URL 规则会拦掉所有公网链接**（误报率是第一 KPI）。

还有 **1 个是把修复本身做坏了**：我为了让"被抑制也留痕"加了一行审计，却因冷却基准取错参照物，把"留痕"改造成了**审计流水无界增长**——被复审在"范围外观察"里提出，我判定必须修（构造性无界不是量级问题）。

**以及最后那一条最有意思**：`isSubagentCaller` 我改了两版才对——第一版太窄、第二版太宽，**两次都错在"自己发明判据"而不是对齐权威源**。定稿是直接抄宿主的判别式。
